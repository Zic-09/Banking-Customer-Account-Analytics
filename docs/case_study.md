# Portfolio Case Study

## Banking Customer & Account Analytics

### Problem
A retail banking team needs reliable visibility into customer accounts, balances, account activity, branch performance and customer tiers. The available operational data contains data-quality issues that must be resolved before reporting.

### Approach
I designed a two-table relational banking dataset and built an end-to-end workflow in MySQL:

1. Profiled raw data
2. Identified missing values, duplicates and inconsistent formats
3. Standardized text and categorical fields
4. Converted dates and financial fields to appropriate data types
5. Validated primary-key and foreign-key relationships
6. Added database constraints
7. Answered business questions with SQL
8. Created a reusable SQL view for Power BI
9. Designed a dashboard framework for executive and financial analysis

### Outcome
The result is a reusable, reporting-ready dataset that connects SQL data preparation with Power BI visualization.

### Key Insight
BI reporting quality depends heavily on the quality of the SQL layer underneath it. A dashboard can be visually attractive and still be unreliable if the underlying data has not been profiled, cleaned and validated.
